# Использование Universal Prompt Optimizer

**Язык:** Русский · [English](USAGE.md)

Адаптивная оптимизация запросов для coding-агентов с учётом активной модели.
Сохраняет замысел и ограничения пользователя без дополнительных LLM-вызовов.

## 1. Установка и запуск

Скачайте текущий [релиз](https://github.com/demyanovvvv/universal-prompt-optimizer/releases/latest)
и распакуйте его. Требуется Python 3.10+. Выполняйте команды из папки релиза.

```bash
./install.sh --ru
```

Выберите агентов, проектную/глобальную область и автоматическую/native-интеграцию.
Для обычной работы оставьте AUTO и Adaptive. В Windows PowerShell:

```powershell
py -3 install.py --agents opencode --auto --lang ru
```

В интерактивном терминале Python предложит область установки и путь проекта.
Полный мастер настроек доступен через Git Bash. Проектная установка действует
в выбранном проекте, глобальная — для текущего пользователя. Перезапустите агент.

Для установки OpenCode без вопросов явно укажите цель:

```bash
python install.py --agents opencode --auto --scope project --project /path/to/project --yes
```

Замените путь; в Windows используйте `py -3` вместо `python`. Для текущего
пользователя задайте `--scope global`. Установка нескольких агентов и dry-run
описаны в [README](README.ru.md#установка).

## 2. Отправьте обычную задачу

При включённой автоматической интеграции пишите запрос как обычно:

```text
Исправь падающий тест входа. Сохрани публичный API и запусти нужные тесты.
```

Указывайте реальные ограничения, точные пути и ожидаемый результат, когда они
важны. Оптимизатор сохраняет их, не придумывает требования и не заменяет знание
проекта. Небольшая задача может остаться небольшой:

```text
Переименуй заголовок «Настройка» в «Установка» в README.ru.md.
```

Для большой задачи явно обозначьте границы:

```text
Добавь пагинацию в существующий поисковый endpoint. Сохрани совместимость ответа,
используй текущий слой БД и добавь тесты для пустой и последней страниц.
```

Оптимизация выполняется в обращении активного агента к модели. Отдельная модель
для переписывания не запускается; корректность реализации не гарантируется.

## 3. Ручные команды

OpenCode устанавливает следующие команды:

| Команда | Результат |
|---|---|
| `/prompt <задача>` | Оптимизация и выполнение |
| `/prompt-only <задача>` | Готовый промпт без выполнения задачи |
| `/prompt-optimizer` | Просмотр или изменение настроек |

Пример:

```text
/prompt-only Проверь изменения авторизации на регрессии. Не редактируй файлы.
```

Профили моделей выбираются внутри оптимизатора; отдельные модельные команды
не нужны. У других агентов точки входа отличаются: используйте соответствующий
[README адаптера](README.ru.md#поддерживаемые-агенты), а не команды OpenCode.

## 4. Режим и качество

**Behavior управляет выполнением:**

- **AUTO:** полезная адаптация и выполнение в пределах разрешений агента.
- **PREVIEW:** показ предложенного задания и запрос подтверждения. Возможность
  принудительно остановить выполнение зависит от адаптера. В OpenCode v1
  подтверждение рекомендательное; Pi поддерживает native-подтверждение.
  Подробности — в [матрице совместимости](COMPATIBILITY.md).
- **OFF:** автоматическая обработка отключена; ручной запуск остаётся доступен.

**Quality gate управляет формой запроса:**

- **Adaptive:** выбирает PASS, LIGHT или FULL по потребностям задачи.
- **Pass:** минимальная нормализация с учётом модели.
- **Light:** только недостающее существенное поле или ограничение.
- **Full:** краткое структурированное задание для выполнения.

По умолчанию используйте Adaptive. FULL не отменяет ограничения пользователя
или разрешения агента. `scope=all` применяется к подходящим обращениям пользователя;
`scope=first` — только к первому, если адаптер умеет отслеживать такой порядок.

Для неизвестной или неоднозначной модели **Skip** не добавляет рекомендации,
а **Generic** использует нейтральные. Другой вариант модели не угадывается.

## 5. Настройка OpenCode

При установленной native-интеграции откройте:

```text
Ctrl+P → command palette → Prompt Optimizer
```

`/po` или `Ctrl+Shift+P` открывает настройки, `/po-status` — native-диалог статуса.
Выберите Behavior, Scope, Quality gate, Unsupported model и Save to.

- **Session:** временная настройка текущей сессии.
- **Project:** `.opencode/prompt-optimizer.json`.
- **Global:** `~/.config/opencode/prompt-optimizer.json`.

Session override может влиять на результат до сброса. Переменные окружения также
участвуют в выборе настроек; см. [README OpenCode](adapters/opencode/README.md).

Индикаторы: `● PO AUTO`, `◐ PO PREVIEW`, `○ PO OFF`, `◇ PO GENERIC`,
`! PO CONFIG` при неверной конфигурации. `*` означает session override.

У инструкционных адаптеров проектный `.prompt-optimizer.json` имеет приоритет
над `~/.config/prompt-optimizer/config.json`. Пример общего конфига:

```json
{
  "schemaVersion": 1,
  "behavior": "auto",
  "scope": "all",
  "qualityGate": "adaptive",
  "unsupportedModel": "skip"
}
```

Подробности для адаптеров — в [руководстве настройки](DECISION-GUIDE.md).

## 6. Обновление и удаление

Распакуйте новый релиз и повторите установку в ту же область и проект.
Python и Bash без мастера сохраняют настройки; мастер Bash позволяет выбрать
новые значения. Затем перезапустите агент.

Перед удалением просмотрите план:

```bash
python uninstall.py --scope project --project /path/to/project --dry-run --yes
python uninstall.py --scope project --project /path/to/project --yes
```

Интерактивные варианты: `bash ./uninstall.sh --ru` и
`py -3 uninstall.py --lang ru`. Для глобальной области задайте `--scope global`.
Удаляются управляемые файлы пакета, метаданные, runtime-состояние и управляемые
блоки с сохранением постороннего содержимого. Проверьте dry-run для нужной
установки и после удаления перезапустите агент.

## 7. Диагностика

| Симптом | Что проверить |
|---|---|
| Нет команд | Выбран нужный агент и область; агент перезапущен; учтены инструкции адаптера |
| Нет индикатора/меню OpenCode | Установлены native server и TUI plugins; OpenCode перезапущен |
| Изменения незаметны | AUTO работает молча, точные запросы остаются краткими; проверьте OFF, first и Skip |
| Видно `! PO CONFIG` | Исправьте неверные настройки; некорректный конфиг отключает автоматическую обработку |
| Настройка не применяется | Проверьте статус, session override, окружение и приоритет project/global |
| Модель не распознана | Проверьте точный runtime ID; для нейтральных рекомендаций выберите Generic |
| PREVIEW не останавливает выполнение | Проверьте возможности адаптера; в OpenCode v1 подтверждение рекомендательное |

Из папки релиза выполните `python install.py --help` или
`python uninstall.py --help` для списка параметров. Проверка пакета:
`python tools/selfcheck.py` или `./verify.sh`.

Оптимизатор не добавляет телеметрию или скрытые сетевые вызовы и не сохраняет
исходные запросы как метрики. Сам агент продолжает обращаться к моделям и управлять
своей историей. См. [Security](SECURITY.md).
